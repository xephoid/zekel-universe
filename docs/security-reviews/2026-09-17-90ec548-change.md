## Findings

### SEC-16-F08 — Watching has no per-client budget

- Severity and confidence: P3, source-confirmed.
- Affected entry point and source link: `GET /api/tables/:id/watch` in [apps/server/src/app.ts](../../apps/server/src/app.ts).
- Actor, preconditions, and violated boundary: anyone can poll many tables' watch endpoints at once; each distinct table costs the engine one resource read per two seconds, so a script naming every table id it knows can drive engine load. Table ids are unguessable, so the reachable set is the tables whose links were shared.
- Expected versus observed behavior: a per-client budget on watch polls (the other public endpoints have one per address); observed only the per-table cache.
- Minimal synthetic reproduction and side-effect assertions: not run.
- Impact and affected milestones: engine availability under a deliberate crowd (M5 and later).
- Proposed fix and regression test: a per-address token bucket on watch (60 per minute), alongside F02's socket budget; a test that a burst is 429.
- Status, owner, next action, and review date: open; owner: server; next action: with F02; review at the next full review.
