## Findings

**The CI end-to-end job could not start its server, and had to be fixed before
any of the above could be checked.** The workflow set `NODE_ENV: production`
and `E2E_TEST_OUTBOX: '1'` on the same step. The server refuses that
combination on purpose — the outbox exposes sign-in links and must never exist
in production — so the process exited immediately with
`E2E_TEST_OUTBOX must never be set in production.` Reproduced directly before
changing anything.

The bind was real: without `NODE_ENV=production` the server did not serve the
built front end, so every page was a 404 and the specs could not sign in;
with it the server would not start at all. The one configuration that served
the app was the one that could not sign in.

Fixed by serving the built app whenever the build output is there — which the
comment on that code already said was the intent — and dropping `NODE_ENV`
from the CI step. All eight browser specs now pass locally against a built
server, in 4.3 minutes: the two-human privacy spec, by-turns with its nudge
email, sign-in and its rejection of a used token, the storefront, and a full
game played through in each of Fractured Fist, Sweetlands and Warble Way.

Severity is not in what it exposed but in what it hid: the privacy spec is the
check that protects a hidden-information game, and it has been unrunnable.
