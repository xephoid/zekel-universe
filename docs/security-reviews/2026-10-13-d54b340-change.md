## What changed

`toWireEvent` now sends the raw engine move only to the seat that made it.
Every other seat gets `engineMove: null`, and so does every seat for an AI
move (its `actorSeatPosition` is null) and a caller with no seat. All three
ways an event leaves the server go through `toWireEvent`: the live broadcast,
the socket replay on `join_table`, and GET `/api/tables/:id/events`. The
summary, the log lines and each seat's own view still tell everyone what
happened; the engine keeps those free of hidden choices.

No per-game allowlist was added. The full review proposed one for clients that
read another seat's move; checking `apps/web/src` found none that need it:

- `Table.tsx` passes `engineMove` and an actor id into the glue. AI moves
  already carried a null actor id there, so glue never used an AI's move.
- Fractured Fist (`glue/ff/read.ts` `identitiesFor`) reads `hand_index` and
  `end_turn` from a move only when the move's actor is the player being
  tracked. For an opponent at a two-human table it now gets null and tracks
  that opponent's cards the same way it already tracked the AI's. Its strike
  (`momentFor`) reads only the views before and after, not the move.
- Warble Way `diceFor` reads `dice` from the move and otherwise parses the
  summary ("Rolled 3, 5"). Other seats now use the summary.
- Sweetlands (`glue/sl/motion.ts`, `SlScreen.tsx` `justPlayed`) reads the move
  only when the actor is this seat.

If a later game needs a public part of another seat's move, the place to add it
is a per-game list of public fields in `toWireEvent`, empty by default.
