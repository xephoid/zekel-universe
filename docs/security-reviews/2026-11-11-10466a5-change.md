# Security review — 2026-11-11 (the admin page, T06)

Mode: change.
Commit and working-tree scope: `10466a5` (server: admin API, schema 8, image
uploads) plus the web commit after it (the `/admin` page, featured order,
screenshots on the game page, the designers list from the database).
Environment: synthetic and local only. In-memory and scratch-file SQLite, the
fake engine, Fastify inject, and headless Chromium against a review server
bound to 127.0.0.1 only.
Prior full review: [2026-11-09](2026-11-09-7f6025b-full.md).
Overall result: no blocking finding. Two limitations recorded (L1, L2) and
one observation outside this change (O1).
Release recommendation: unchanged from the last full review.

## What changed

- New routes: `GET /api/admin/content`; `PUT /api/admin/games/:id`;
  `POST /api/admin/designers`, `PUT /api/admin/designers/:slug`;
  `POST /api/admin/updates`, `PUT` and `DELETE /api/admin/updates/:id`;
  `POST /api/admin/media`; `GET /media/:id` (public); `GET /api/designers`
  (public). `GET /api/me` gains `isAdmin` for the caller's own account.
- New configuration: `ADMIN_EMAILS`, empty by default.
- Schema 8: games gain designer slug, cover focus, screenshots, featured
  place; updates gain a removed time; new `designers` and `media` tables.

Browser walk (headless Chromium, 1440 × 900): a non-admin account sees "not
an admin" and no Admin link; the admin edits Fractured Fist's blurb, sets it
featured, uploads a screenshot, and the game page and home show both; a cover
link to another site is refused with the server's message; a new designer
with an uploaded portrait appears on `/designers`; an update is posted and a
seeded one removed, and the home feed follows. The only console errors were
the browser blocking the deliberately bad cover link (CSP) and that request's
400.

## Limitations

- **L1 — no upload quota.** An admin can upload any number of images; each is
  stored in the database as base64. Acceptable while admins are the site's
  own staff. Trigger to revisit: any non-staff uploader (designer self-serve),
  or database size alerts. Images nothing points at any more are not cleaned
  up (recorded as open in `docs/implementation-plan.md` §21).
- **L2 — uploads served from the app's own origin, no dimension check.** The
  playbook asks for untrusted content on an isolated origin. Here only admins
  upload, only PNG, JPEG and WebP pass, and `nosniff` keeps a browser from
  reading one as anything else. Trigger to revisit: the same as L1, which
  would make the content untrusted.

## Observation outside this change

- **O1 — the server binds every interface.** `apps/server/src/index.ts`
  listens on `0.0.0.0`. During this review a local review server with the
  test outbox on (sign-in links readable over HTTP) was reachable on every
  address the machine has, including a public one, for about a minute before
  it was stopped. The outbox already refuses to start in production; the
  risk is to local review servers only. Suggested follow-up: a `HOST`
  setting, defaulting to `127.0.0.1` outside production.
