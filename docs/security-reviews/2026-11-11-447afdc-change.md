# Security review — 2026-11-11 (site analytics, T07)

Mode: change.
Commit and working-tree scope: `2b1a873` (server: PostHog settings,
`/api/config`, page policy) and `447afdc` (web: pageviews and app events,
`posthog-js` added), on branch `claude/posthog-site-analytics` from `main`
`ebd3f9b`.
Environment: synthetic and local only. In-memory SQLite, the fake engine,
Fastify inject, and headless Chromium against the Vite dev server with every
`/api` call and every PostHog request answered inside the test browser.
Nothing reached a real server or PostHog. The project key used is made up.
Prior full review: [2026-11-09](2026-11-09-7f6025b-full.md).
Overall result: no blocking finding. Two limitations recorded (L1, L2).
Release recommendation: unchanged from the last full review.

## What changed

- New route: `GET /api/config` (public, no principal), answering
  `{ analytics: { key, host } | null }`.
- New configuration: `POSTHOG_KEY`, `POSTHOG_HOST`, both empty by default.
- The page's Content-Security-Policy gains the PostHog host in `connect-src`
  when the key is set. Nothing else in the policy changes.
- New browser dependency: `posthog-js` 1.440.0 (published 2026-10-27), loaded
  as a separate file only when analytics is on.

`navigator.userAgentData` and used a desktop user agent in the test browser

## Limitations

- **L1 — no consent notice.** Analytics starts on the first visit for
  everyone who has not set Do Not Track. It stores a random visitor id in
  browser storage and sends pageviews and the events above. No legal review
  was done. Trigger to revisit: before launch in places that require consent
  for analytics storage, or before adding anything beyond this list.
- **L2 — a large third-party library in the page.** `posthog-js` runs with
  full access to the page it loads in, including during games. It is pinned,
  loaded only when the key is set, and kept from loading further code.
  Trigger to revisit: each version bump (read the changelog and recheck that
  nothing new loads remotely), or a move to sending events through the
  site's own server instead.
