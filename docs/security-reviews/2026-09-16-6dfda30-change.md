## Findings

### SEC-18-F01 — GitHub Actions pinned by tag, not by commit

- Severity and confidence: P3, source-confirmed.
- Affected entry point and source link: [.github/workflows/ci.yml](../../.github/workflows/ci.yml).
- Actor, preconditions, and violated boundary: a compromised action tag could run arbitrary code in CI; the workflow has no deployment secrets, so the reachable impact is the CI runner and the engine token used for the in-job engine container.
- Expected versus observed behavior: actions pinned to immutable revisions; observed `actions/checkout@v4` and similar tags.
- Minimal synthetic reproduction and side-effect assertions: not applicable (configuration).
- Impact and affected milestones: CI integrity for every milestone.
- Proposed fix and regression test: pin each action to a reviewed commit SHA with a version comment; enable Dependabot or Renovate for actions.
- Status, owner, next action, and review date: open; owner: repository maintainer; next action: pin before the first deploy; review at the next full review.

### SEC-08-F02 — No per-connection message rate limit or idempotency key

- Severity and confidence: P3, source-confirmed.
- Affected entry point and source link: the `move`, `undo` and `join_table` socket handlers in [apps/server/src/app.ts](../../apps/server/src/app.ts).
- Actor, preconditions, and violated boundary: a seated player can send moves as fast as the socket allows; each is serialized per table and validated by the engine, so no rule is broken, but the engine process is shared and a flood delays other tables.
- Expected versus observed behavior: a bounded number of messages per connection per second and a client-supplied request id that makes a redelivered move a no-op; observed neither.
- Minimal synthetic reproduction and side-effect assertions: two concurrent moves are serialized (`hardening.test.ts`); a burst test was not run.
- Impact and affected milestones: availability of the single engine process (M2 and later, when strangers share it).
- Proposed fix and regression test: a token bucket per socket, and a `requestId` on the move message remembered per table for a short window; a test that sends a burst and asserts bounded engine calls.
- Status, owner, next action, and review date: open; owner: server; next action: with the M2 pass; review then.

### SEC-04-F03 — Session identifier is not rotated on re-authentication; local snapshot survives sign-out

- Severity and confidence: P3, source-confirmed.
- Affected entry point and source link: `POST /api/auth/email/complete` and `POST /api/auth/signout` in [apps/server/src/app.ts](../../apps/server/src/app.ts); [apps/web/src/table/useTable.ts](../../apps/web/src/table/useTable.ts).
- Actor, preconditions, and violated boundary: completing a sign-in while already signed in issues a second session without revoking the first; after sign-out the browser keeps its own last table event in local storage.
- Expected versus observed behavior: prior sessions revoked on re-authentication; private local state cleared on sign-out. Observed: extra sessions accumulate until they expire; the snapshot stays (it belongs to the same browser's own seat).
- Minimal synthetic reproduction and side-effect assertions: sign in twice with the same browser and count `auth_sessions` rows.
- Impact and affected milestones: shared-device hygiene (M2).
- Proposed fix and regression test: delete the caller's other sessions on completion; clear `universe:` keys from local storage on sign-out; tests for both.
- Status, owner, next action, and review date: open; owner: server and web; next action: with the M2 pass; review then.
