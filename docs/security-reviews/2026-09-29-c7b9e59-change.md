## What changed

- **Origin check.** Every request that is not GET, HEAD or OPTIONS must come
  from an allowed origin, whatever its path. Before, only raw paths starting
  with `/api/` were checked, so `/%61pi/...` skipped it. Static files are GET
  only, and the socket's own requests never reach Fastify (`sockets.ts`
  checks their origin), so nothing that used to work needs the old gap. A
  request with no Origin header is still let through (the existing policy for
  non-browser clients).
- **Header split.** A new helper, `isApiRequest`, asks the matched route
  (`req.routeOptions.url`) first, then the decoded path. A path that will not
  decode counts as API. `onSend` uses it to pick no-store (API) or the page
  policy (everything else).
- **Page fallback.** The not-found handler uses the same helper, so
  `GET /%61pi/nope` gets the JSON 404 rather than `index.html`. Side effect:
  `GET /apiary` (not an API path) now gets the page instead of a JSON 404.
