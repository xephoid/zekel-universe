The eight primitives
Every game board on this platform is composed from these eight parts and nothing else. Design them once, with their states and their motion, and every game inherits them. The Sweetlands table on this canvas is a composition of them; the last section says which part is which. The field lists under each one are the exact data the engine hands the component today, so the design and the code agree on what a card or a track is.

One way to touch everything
Every primitive tells the table the same thing when tapped: which kind of part, which id, which label. The table decides what the tap means; the part never does. Legal-move highlighting, selection, and disabled are states the table sets on the part. There is no separate hit layer over the board.
select → { component, id, label }
Games bring colors, not parts
A primitive never hard-codes a game's colors. Each card, piece, cell, and region carries a color key; the game supplies a palette that maps keys to colors, and the primitives read it. Sweetlands maps its six space colors and five factions; Cybernoir maps stamp red and glacier blue; a new game maps its own and gets the whole set for free.

Not a primitive
The Roll (dice in the battle modal), the Draw prompt, the lesson popup, the slideshow caption, and the top bar are table chrome. They are the same on every game and live above the board.
